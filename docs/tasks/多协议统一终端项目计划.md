# 多协议统一终端项目计划

## 一、项目定位

本项目面向“多协议车载/工业智能网关”设计赛，基于 **Milk-V Duo 256M** 作为主控平台，设计一款能够将多种外部通信协议统一接入，并最终转换为 **CAN 总线数据** 的多协议统一终端。

项目核心目标是：实现 **4G、WiFi、蓝牙、以太网、RS485 等多种通信方式到 CAN 总线的统一转换**，并通过异构多核协同方式提升系统实时性、稳定性和低功耗能力。

整体设计思路是：

```text
外部多协议数据接入
        ↓
大核解析协议帧
        ↓
统一封装数据
        ↓
发送给小核
        ↓
小核 RTOS 实时转发到 CAN
        ↓
C51 负责低功耗唤醒管理
```

---

## 二、项目整体逻辑

本项目采用“三层协同”的系统架构：

### 1. 大核：协议接入与数据解析层

Milk-V Duo 256M 的大核主要负责运行 Linux 系统，承担复杂协议的接入和解析工作。

大核负责处理：

- USB 转 4G 模块
- USB 转蓝牙/WiFi 二合一模块
- 以太网通信
- RS485 数据接收
- 不同协议帧的数据解析
- 统一数据格式封装
- 与小核之间的数据通信

大核不直接负责 CAN 的实时发送，而是把解析后的数据统一整理成内部标准数据帧，再交给小核处理。

这样设计的好处是：大核适合处理网络协议、文件系统、驱动适配、复杂数据解析等任务；小核则专注于实时控制和 CAN 转发，避免 Linux 调度不确定性影响 CAN 实时性。

### 2. 小核：RTOS 实时转发层

小核运行 RTOS，主要负责实时任务。

小核接收大核发送来的统一数据帧后，根据帧中的目标信息、CAN ID、数据长度、数据内容等字段，将数据转发到 CAN 总线上。

小核主要负责：

- 接收大核发送的统一数据帧
- 解析内部统一帧格式
- CAN 报文组包
- CAN 报文实时发送
- CAN 接收数据回传给大核
- CAN 总线状态检测
- 异常处理，例如 CAN 发送失败、总线错误、超时等

小核的核心价值是保证 CAN 侧通信的实时性和稳定性。

### 3. C51：低功耗唤醒层

系统额外使用一个 C51 单片机作为低功耗管理单元。

当外部没有数据传输时，系统进入低功耗状态；当 4G、WiFi、蓝牙、以太网或 RS485 任意一路有数据到来时，C51 负责检测唤醒信号，并唤醒主控系统进入正常工作状态。

C51 主要负责：

- 低功耗状态管理
- 外部唤醒信号检测
- 唤醒 Milk-V Duo 256M
- 控制部分外设电源
- LED 状态指示
- 防止系统长期无数据时无意义耗电

## 三、系统功能规划

### 1. 4G 转 CAN

使用 USB 转 4G 模块接入网络。

主要功能：

- 4G 模块联网
- 支持 TCP/MQTT 通信
- 接收云端下发数据
- 大核解析网络数据帧
- 统一封装后发送给小核
- 小核转换为 CAN 报文发送

典型数据流：

```text
云端服务器 / MQTT / TCP
        ↓
USB 4G 模块
        ↓
Milk-V Duo 大核 Linux
        ↓
协议解析 + 统一封装
        ↓
小核 RTOS
        ↓
CAN 总线
```

### 2. WiFi 转 CAN

使用 USB 转蓝牙/WiFi 二合一模块中的 WiFi 功能。

主要功能：

- WiFi 连接局域网
- 支持 TCP/UDP 通信
- 接收 PC 或上位机发送的数据
- 转换为 CAN 报文
- 支持 CAN 数据回传到 WiFi 端

典型应用场景：

```text
PC 上位机
   ↓ UDP/TCP
WiFi 模块
   ↓
大核协议解析
   ↓
小核 CAN 转发
   ↓
CAN 设备
```

### 3. 蓝牙转 CAN

使用 USB 蓝牙模块实现手机端或其他蓝牙设备与 CAN 总线之间的数据转换。

主要功能：

- 手机蓝牙连接终端
- 手机发送控制数据
- 大核接收蓝牙数据
- 解析后统一封装
- 小核发送 CAN 报文
- CAN 返回数据可通过蓝牙回传手机

典型数据流：

```text
手机蓝牙
   ↓
USB 蓝牙模块
   ↓
大核蓝牙数据解析
   ↓
统一协议封装
   ↓
小核 RTOS
   ↓
CAN 总线
```

### 4. 以太网转 CAN

利用底板以太网接口，实现局域网内 PC 上位机与 CAN 总线之间的数据转换。

主要功能：

- 支持 TCP 或 UDP 通信
- PC 端发送控制指令
- 网关接收后转换为 CAN 报文
- CAN 数据可回传至 PC
- 可作为调试和演示的主要通道

典型数据流：

```text
PC 上位机
   ↓ TCP/UDP
以太网接口
   ↓
大核 Linux
   ↓
协议解析
   ↓
小核 RTOS
   ↓
CAN 总线
```

### 5. RS485 转 CAN

利用底板自带 RS485 接口，完成工业现场常用串口总线到 CAN 总线的转换。

主要功能：

- 接收 RS485 数据
- 支持自定义协议或 Modbus RTU 协议
- 提取有效数据
- 转换成统一内部数据帧
- 发送到小核
- 小核转发至 CAN

典型数据流：

```text
RS485 设备
   ↓
RS485 接口
   ↓
大核串口读取
   ↓
协议解析
   ↓
小核 RTOS
   ↓
CAN 总线
```

## 五、内部统一数据帧设计

为了让不同协议最终都能转成 CAN，建议设计一个统一内部数据帧。

示例格式：

```c
typedef struct {
    uint8_t  src_type;      // 数据来源：4G/WiFi/蓝牙/以太网/RS485
    uint8_t  frame_type;    // 帧类型：控制帧/状态帧/配置帧/心跳帧
    uint32_t can_id;        // 目标 CAN ID
    uint8_t  can_dlc;       // CAN 数据长度
    uint8_t  data[8];       // CAN 数据内容，经典 CAN 最大 8 字节
    uint16_t crc;           // 校验
} unified_frame_t;
```

其中 `src_type` 可以这样定义：

```c
#define SRC_4G       0x01
#define SRC_WIFI     0x02
#define SRC_BT       0x03
#define SRC_ETH      0x04
#define SRC_RS485    0x05
#define SRC_CAN      0x06
```

这样做的好处是：无论数据来自 4G、WiFi、蓝牙、以太网还是 RS485，大核最终都把它转换成统一格式，小核只需要识别一种内部协议即可。

## 六、软件架构规划

### 1. 大核 Linux 软件框架

大核程序可以采用多线程或事件循环方式设计。

建议模块如下：

```text
main
├── 4g_task
├── wifi_task
├── bluetooth_task
├── ethernet_task
├── rs485_task
├── protocol_parser
├── unified_frame_pack
├── ipc_send_to_rtos
└── log_debug
```

每个协议入口负责接收数据，统一交给 `protocol_parser` 解析，然后调用 `unified_frame_pack` 打包，最后通过大小核通信接口发送给小核。

### 2. 小核 RTOS 软件框架

小核程序重点是实时性和稳定性。

建议模块如下：

```text
RTOS
├── ipc_receive_task
├── can_tx_task
├── can_rx_task
├── can_error_task
├── watchdog_task
└── status_report_task
```

其中：

- `ipc_receive_task`：接收大核发送来的统一数据帧
- `can_tx_task`：将统一数据帧转换成 CAN 报文并发送
- `can_rx_task`：接收 CAN 总线返回数据
- `can_error_task`：处理 CAN 总线错误
- `watchdog_task`：防止系统卡死
- `status_report_task`：把 CAN 状态回传给大核

### 3. C51 低功耗软件框架

C51 程序相对简单，主要负责状态检测和唤醒。

```text
C51
├── low_power_mode
├── wakeup_detect
├── power_control
├── led_control
└── heartbeat_check
```

工作逻辑：

```text
系统无数据
   ↓
C51 控制进入低功耗状态
   ↓
检测 4G/WiFi/蓝牙/以太网/RS485 是否有数据
   ↓
如果有数据到来
   ↓
唤醒 Milk-V Duo 256M
   ↓
系统恢复正常通信
```

## 七、硬件规划

### 1. 主控部分

- 主控板：Milk-V Duo 256M
- 大核：运行 Linux，负责多协议接入与解析
- 小核：运行 RTOS，负责 CAN 实时转发

### 2. 通信接口部分

| 通信方式 | 硬件来源 | 目标功能 |
|---|---|---|
| 4G | USB 转 4G 模块 | 4G 转 CAN |
| WiFi | USB 蓝牙/WiFi 二合一模块 | WiFi 转 CAN |
| 蓝牙 | USB 蓝牙/WiFi 二合一模块 | 蓝牙转 CAN |
| 以太网 | 底板自带接口 | 以太网转 CAN |
| RS485 | 底板自带接口 | RS485 转 CAN |
| CAN | 外接 CAN 收发器/底板 CAN 接口 | 统一 CAN 输出 |

### 3. 低功耗部分

- C51 单片机
- 电源控制电路
- 外部唤醒检测电路
- LED 状态指示灯

### 4. 外壳与展示

根据比赛要求，最终作品需要封装在黑盒结构中，建议外部只保留：

- DC 电源接口
- CAN/DB9 接口
- RJ45 以太网接口
- SMA 天线接口或内置天线
- LED 状态灯
- 必要的 USB 调试口

## 九、项目亮点总结

### 1. 多协议统一接入

系统支持 4G、WiFi、蓝牙、以太网、RS485 等多种通信方式，能够适配车载和工业现场中常见的不同通信场景。

### 2. 统一协议封装

不同来源的数据不会直接混乱地转发到 CAN，而是先由大核进行协议解析，再统一封装成内部标准帧，提高了系统的可扩展性和可维护性。

### 3. 大小核协同架构

大核负责复杂协议解析，小核负责 CAN 实时转发，充分利用 Milk-V Duo 256M 的异构多核能力。

### 4. RTOS 保证 CAN 实时性

CAN 总线通信对实时性要求较高，因此由小核运行 RTOS 进行专门处理，避免 Linux 系统调度延迟影响 CAN 转发。

### 5. 支持低功耗唤醒

使用 C51 作为低功耗管理单元，在无数据时进入低功耗状态，在有数据到来时自动唤醒系统，提升了项目的工程完整性。

### 6. 黑盒式网关终端设计

作品最终可以封装为一个独立黑盒网关，只暴露必要接口，符合比赛对实体作品和工业化设计的要求。
