# 多协议统一终端项目计划

## 一、项目定位

本项目面向“多协议车载/工业智能网关”设计赛，基于 **Milk-V Duo 256M** 作为主控平台，设计一款能够将多种外部通信协议统一接入，并最终转换为 **CAN 总线数据** 的多协议统一终端。

项目核心目标是：实现 **4G、WiFi、蓝牙、以太网、RS485 等多种通信方式到 CAN 总线的统一转换**，并通过异构多核协同、Web 可视化监控方式提升系统实时性、稳定性、可维护性和低功耗能力。

整体设计思路是：

```text
外部多协议数据接入
        ↓
大核解析协议帧
        ↓
统一封装数据
        ↓
发送给小核
        ↓
小核 RTOS 实时转发到 CAN
        ↓
C51 负责低功耗唤醒管理

大核同步维护协议业务状态和日志
        ↓
Rust Web 后端读取业务快照、系统资源和日志
        ↓
Vue3 页面展示连通性、资源占用和系统日志
```

## 二、项目整体逻辑

本项目采用“三层协同 + Web 监控展示”的系统架构：

### 1. 大核：协议接入与数据解析层

Milk-V Duo 256M 的大核主要负责运行 Linux 系统，承担复杂协议的接入和解析工作。

大核负责处理：

- USB 转 4G 模块
- USB 转蓝牙/WiFi 二合一模块
- 以太网通信
- RS485 数据接收
- 不同协议帧的数据解析
- 统一数据格式封装
- 与小核之间的数据通信
- 各协议模块连通性状态采集
- 系统日志和协议业务状态整理
- 向 Web 模块提供业务状态 JSON 快照

大核不直接负责 CAN 的实时发送，而是把解析后的数据统一整理成内部标准数据帧，再交给小核处理。

这样设计的好处是：大核适合处理网络协议、文件系统、驱动适配、复杂数据解析等任务；小核则专注于实时控制和 CAN 转发，避免 Linux 调度不确定性影响 CAN 实时性。

### 2. 小核：RTOS 实时转发层

小核运行 RTOS，主要负责实时任务。

小核接收大核发送来的统一数据帧后，根据帧中的目标信息、CAN ID、数据长度、数据内容等字段，将数据转发到 CAN 总线上。

小核主要负责：

- 接收大核发送的统一数据帧
- 解析内部统一帧格式
- CAN 报文组包
- CAN 报文实时发送
- CAN 接收数据回传给大核
- CAN 总线状态检测
- 异常处理，例如 CAN 发送失败、总线错误、超时等

小核的核心价值是保证 CAN 侧通信的实时性和稳定性。

### 3. C51：低功耗唤醒层

系统额外使用一个 C51 单片机作为低功耗管理单元。

当外部没有数据传输时，系统进入低功耗状态；当 4G、WiFi、蓝牙、以太网或 RS485 任意一路有数据到来时，C51 负责检测唤醒信号，并唤醒主控系统进入正常工作状态。

C51 主要负责：

- 低功耗状态管理
- 外部唤醒信号检测
- 唤醒 Milk-V Duo 256M
- 控制部分外设电源
- LED 状态指示
- 防止系统长期无数据时无意义耗电

### 4. Web：监控展示与调试运维层

Web 模块运行在大核 Linux 侧，主要面向比赛演示、现场联调和后续运维查看。

Web 模块不参与 CAN 实时发送，也不改变“外部协议输入 → 大核封装 → 小核转发”的主业务链路。后端使用 Rust + Axum/Tokio，并按 `riscv64gc-unknown-linux-musl` 静态交叉编译为 `put-webd` 单个可执行程序；前端使用 Vue3 + Vite，构建后的 `dist/` 作为外置静态文件由后端托管。

Web 数据来源采用混合分工：系统资源、设备存在性和日志文件由 Web 后端直接读取；4G、WiFi、蓝牙、以太网、RS485、CAN、大小核通信等业务状态由 `linux_app` 周期写入 `/run/put/status/`，Web 后端只读展示。

Web 模块主要负责：

- 展示 4G、WiFi、蓝牙、以太网、RS485、CAN、大小核通信的连通性
- 展示各协议模块的收发计数、错误计数、最近通信时间
- 展示 CPU、内存、磁盘、网络、系统运行时间等资源占用
- 展示大核应用日志、协议解析日志、CAN 异常日志和系统启动日志
- 展示异常告警，例如模块断连、IPC 超时、CRC 错误、CAN 总线错误等
- 为答辩演示提供直观的系统运行状态界面
- 保持局域网只读访问，不提供写接口或小核控制接口

## 三、系统功能规划

### 1. 4G 转 CAN

使用 USB 转 4G 模块接入网络。

主要功能：

- 4G 模块联网
- 支持 TCP/MQTT 通信
- 接收云端下发数据
- 大核解析网络数据帧
- 统一封装后发送给小核
- 小核转换为 CAN 报文发送

典型数据流：

```text
云端服务器 / MQTT / TCP
        ↓
USB 4G 模块
        ↓
Milk-V Duo 大核 Linux
        ↓
协议解析 + 统一封装
        ↓
小核 RTOS
        ↓
CAN 总线
```

### 2. WiFi 转 CAN

使用 USB 转蓝牙/WiFi 二合一模块中的 WiFi 功能。

主要功能：

- WiFi 连接局域网
- 支持 TCP/UDP 通信
- 接收 PC 或上位机发送的数据
- 转换为 CAN 报文
- 支持 CAN 数据回传到 WiFi 端

典型应用场景：

```text
PC 上位机
   ↓ UDP/TCP
WiFi 模块
   ↓
大核协议解析
   ↓
小核 CAN 转发
   ↓
CAN 设备
```

### 3. 蓝牙转 CAN

使用 USB 蓝牙模块实现手机端或其他蓝牙设备与 CAN 总线之间的数据转换。

主要功能：

- 手机蓝牙连接终端
- 手机发送控制数据
- 大核接收蓝牙数据
- 解析后统一封装
- 小核发送 CAN 报文
- CAN 返回数据可通过蓝牙回传手机

典型数据流：

```text
手机蓝牙
   ↓
USB 蓝牙模块
   ↓
大核蓝牙数据解析
   ↓
统一协议封装
   ↓
小核 RTOS
   ↓
CAN 总线
```

### 4. 以太网转 CAN

利用底板以太网接口，实现局域网内 PC 上位机与 CAN 总线之间的数据转换。

主要功能：

- 支持 TCP 或 UDP 通信
- PC 端发送控制指令
- 网关接收后转换为 CAN 报文
- CAN 数据可回传至 PC
- 可作为调试和演示的主要通道

典型数据流：

```text
PC 上位机
   ↓ TCP/UDP
以太网接口
   ↓
大核 Linux
   ↓
协议解析
   ↓
小核 RTOS
   ↓
CAN 总线
```

### 5. RS485 转 CAN

利用底板自带 RS485 接口，完成工业现场常用串口总线到 CAN 总线的转换。

主要功能：

- 接收 RS485 数据
- 支持自定义协议或 Modbus RTU 协议
- 提取有效数据
- 转换成统一内部数据帧
- 发送到小核
- 小核转发至 CAN

典型数据流：

```text
RS485 设备
   ↓
RS485 接口
   ↓
大核串口读取
   ↓
协议解析
   ↓
小核 RTOS
   ↓
CAN 总线
```

### 6. Web 监控展示

在大核 Linux 上运行 Rust Web 后端服务，用户通过浏览器访问 Vue3 监控页面。

主要功能：

- 展示 4G、WiFi、蓝牙、以太网、RS485、CAN、大小核通信状态
- 展示当前 CPU、内存、磁盘、网络流量、系统运行时间
- 展示协议接收、解析、封装、发送、回传的统计计数
- 支持系统日志分页查看、等级过滤和关键字搜索
- 支持最近异常事件展示，例如模块断连、CAN 错误、IPC 超时
- 支持演示模式，便于在硬件未全部接入时展示页面效果
- 后端以 `put-webd` 单个静态可执行文件部署，前端 `dist/` 外置部署

典型访问流程：

```text
PC / 手机浏览器
   ↓ HTTP
Milk-V Duo 大核 put-webd
   ↓
读取 /run/put/status 快照 / 日志文件 / 系统资源
   ↓
Vue3 页面展示系统运行状态
```

## 五、内部统一数据帧设计

为了让不同协议最终都能转成 CAN，建议设计一个统一内部数据帧。

示例格式：

```c
typedef struct {
    uint8_t  src_type;      // 数据来源：4G/WiFi/蓝牙/以太网/RS485
    uint8_t  frame_type;    // 帧类型：控制帧/状态帧/配置帧/心跳帧
    uint32_t can_id;        // 目标 CAN ID
    uint8_t  can_dlc;       // CAN 数据长度
    uint8_t  data[8];       // CAN 数据内容，经典 CAN 最大 8 字节
    uint16_t crc;           // 校验
} unified_frame_t;
```

其中 `src_type` 可以这样定义：

```c
#define SRC_4G       0x01
#define SRC_WIFI     0x02
#define SRC_BT       0x03
#define SRC_ETH      0x04
#define SRC_RS485    0x05
#define SRC_CAN      0x06
```

这样做的好处是：无论数据来自 4G、WiFi、蓝牙、以太网还是 RS485，大核最终都把它转换成统一格式，小核只需要识别一种内部协议即可。

## 六、软件架构规划

### 1. 大核 Linux 软件框架

大核程序可以采用多线程或事件循环方式设计。

建议模块如下：

```text
main
├── 4g_task
├── wifi_task
├── bluetooth_task
├── ethernet_task
├── rs485_task
├── protocol_parser
├── unified_frame_pack
├── ipc_send_to_rtos
├── status_collector
├── log_manager
└── log_debug
```

每个协议入口负责接收数据，统一交给 `protocol_parser` 解析，然后调用 `unified_frame_pack` 打包，最后通过大小核通信接口发送给小核。与此同时，`status_collector` 记录各模块连通性、收发统计、解析错误和最近通信时间，并周期写入 `/run/put/status/`；`log_manager` 写入 `/var/log/put/`，供 Web 模块只读查看。系统资源占用由 Web 后端直接从 `/proc`、`/sys`、`/dev` 中读取，`linux_app` 不承担 Web API 或页面逻辑。

### 2. 小核 RTOS 软件框架

小核程序重点是实时性和稳定性。

建议模块如下：

```text
RTOS
├── ipc_receive_task
├── can_tx_task
├── can_rx_task
├── can_error_task
├── watchdog_task
└── status_report_task
```

其中：

- `ipc_receive_task`：接收大核发送来的统一数据帧
- `can_tx_task`：将统一数据帧转换成 CAN 报文并发送
- `can_rx_task`：接收 CAN 总线返回数据
- `can_error_task`：处理 CAN 总线错误
- `watchdog_task`：防止系统卡死
- `status_report_task`：把 CAN 状态回传给大核

### 3. C51 低功耗软件框架

C51 程序相对简单，主要负责状态检测和唤醒。

```text
C51
├── low_power_mode
├── wakeup_detect
├── power_control
├── led_control
└── heartbeat_check
```

工作逻辑：

```text
系统无数据
   ↓
C51 控制进入低功耗状态
   ↓
检测 4G/WiFi/蓝牙/以太网/RS485 是否有数据
   ↓
如果有数据到来
   ↓
唤醒 Milk-V Duo 256M
   ↓
系统恢复正常通信
```

### 4. Web 监控展示软件框架

Web 模块建议采用“Rust 后端 API + Vue3 前端静态页面”的轻量结构。

建议模块如下：

```text
Web
├── put-webd
├── status_api
├── resource_api
├── log_api
├── event_api
└── vue3_frontend
```

其中：

- `put-webd`：Rust Axum/Tokio 后端，静态交叉编译为单个可执行文件
- `status_api`：返回各协议模块、大小核通信、CAN 总线的连通性状态
- `resource_api`：后端直接读取 `/proc`、`/sys`、`/dev` 并返回 CPU、内存、磁盘、网络、运行时间等资源数据
- `log_api`：返回日志分页、等级过滤、关键字搜索结果
- `event_api`：返回最近异常事件和告警状态
- `vue3_frontend`：Vue3 + Vite 前端，构建后的外置 `dist/` 由后端托管

Web 模块第一版以局域网只读监控为主，避免在页面上直接提供会影响 CAN 实时链路的控制操作。

## 七、硬件规划

### 1. 主控部分

- 主控板：Milk-V Duo 256M
- 大核：运行 Linux，负责多协议接入与解析
- 小核：运行 RTOS，负责 CAN 实时转发

### 2. 通信接口部分

| 通信方式 | 硬件来源                      | 目标功能      |
| -------- | ----------------------------- | ------------- |
| 4G       | USB 转 4G 模块                | 4G 转 CAN     |
| WiFi     | USB 蓝牙/WiFi 二合一模块      | WiFi 转 CAN   |
| 蓝牙     | USB 蓝牙/WiFi 二合一模块      | 蓝牙转 CAN    |
| 以太网   | 底板自带接口                  | 以太网转 CAN  |
| RS485    | 底板自带接口                  | RS485 转 CAN  |
| CAN      | 外接 CAN 收发器/底板 CAN 接口 | 统一 CAN 输出 |

### 3. 低功耗部分

- C51 单片机
- 电源控制电路
- 外部唤醒检测电路
- LED 状态指示灯

### 4. 外壳与展示

根据比赛要求，最终作品需要封装在黑盒结构中，建议外部只保留：

- DC 电源接口
- CAN/DB9 接口
- RJ45 以太网接口
- SMA 天线接口或内置天线
- LED 状态灯
- 必要的 USB 调试口
- Web 访问可复用 RJ45 以太网或 WiFi 网络，不需要额外独立接口

## 九、项目亮点总结

### 1. 多协议统一接入

系统支持 4G、WiFi、蓝牙、以太网、RS485 等多种通信方式，能够适配车载和工业现场中常见的不同通信场景。

### 2. 统一协议封装

不同来源的数据不会直接混乱地转发到 CAN，而是先由大核进行协议解析，再统一封装成内部标准帧，提高了系统的可扩展性和可维护性。

### 3. 大小核协同架构

大核负责复杂协议解析，小核负责 CAN 实时转发，充分利用 Milk-V Duo 256M 的异构多核能力。

### 4. RTOS 保证 CAN 实时性

CAN 总线通信对实时性要求较高，因此由小核运行 RTOS 进行专门处理，避免 Linux 系统调度延迟影响 CAN 转发。

### 5. 支持低功耗唤醒

使用 C51 作为低功耗管理单元，在无数据时进入低功耗状态，在有数据到来时自动唤醒系统，提升了项目的工程完整性。

### 6. Web 可视化监控展示

系统提供 Web 监控页面，可以直观看到各通信模块连通性、系统资源占用、CAN 状态和运行日志，便于现场调试、问题定位和比赛答辩演示。

### 7. 黑盒式网关终端设计

作品最终可以封装为一个独立黑盒网关，只暴露必要接口，符合比赛对实体作品和工业化设计的要求。
