# anyMSG 统一数据帧设计

版本号：0.2.1
修改时间：2026-05-25
文档定位：只描述 anyMSG 统一数据帧格式与字段语义

---

## 1. 文档边界

本文只定义 anyMSG 统一数据帧本身，包括帧结构、字段含义、CID 地址段、`type` 类型和基础合法性约束。

网关接入、路由、共享内存、分片重组、队列调度和发送流程见《整体架构设计》。

---

## 2. 帧结构

anyMSG 由 40B 固定帧头和可变长度 payload 组成。

```yaml
anyMSG_protocol_structure:
  msg_length: 2Byte          # 帧总字节数，等于 40 + payload_length
  retries: 1Byte             # 重试次数
  __RESERVED__: 1Byte        # 保留字段
  __SRCHLD__: 4Byte          # 源标记，保留
  destination_cid: 4Byte     # 目的通信地址
  source_cid: 4Byte          # 源通信地址
  local_time: 4Byte          # 本地时间戳
  verify_string[16]: 16Byte  # 校验码
  payload_length: 2Byte      # payload 字节数
  type: 1Byte                # payload 类型
  __PADDING__: 1Byte         # 填充字段
  payload: variable          # 数据帧负载实体
```

固定帧头长度计算：

```text
2 + 1 + 1 + 4 + 4 + 4 + 4 + 16 + 2 + 1 + 1 = 40 Byte
```

---

## 3. 字段规则

| 字段                | 长度 | 规则                                              |
| ------------------- | ---: | ------------------------------------------------- |
| `msg_length`        |   2B | anyMSG 完整帧长度，必须等于 `40 + payload_length` |
| `retries`           |   1B | 重试次数；当前无端到端重试机制，默认填 `1`        |
| `__RESERVED__`      |   1B | 保留字段，当前填 `0x00`                           |
| `__SRCHLD__`        |   4B | 保留字段，当前填 `0x00000000`                     |
| `destination_cid`   |   4B | 目的通信地址                                      |
| `source_cid`        |   4B | 源通信地址                                        |
| `local_time`        |   4B | 发送端本地时间戳                                  |
| `verify_string[16]` |  16B | 校验算法未定义，当前填 `0x00`                     |
| `payload_length`    |   2B | payload 字节数，不包含 40B 帧头                   |
| `type`              |   1B | payload 类型                                      |
| `__PADDING__`       |   1B | 填充字段，当前填 `0x00`                           |
| `payload`           | 可变 | 业务负载，由 `type` 决定语义                      |

注意：

- `msg_length` 描述完整 anyMSG 帧长度；
- `payload_length` 只描述 payload 长度；
- `verify_string[16]` 当前不能作为有效业务校验依据；
- 多字节字段的字节序需要在具体通信接口实现中保持一致。

---

## 4. CID 地址段

`destination_cid` 和 `source_cid` 都使用 4B 通信地址。地址首字节用于区分设备或接口地址段，低 3 字节由对应接口或业务层继续解释。

| 地址首字节    | 定义              |
| ------------- | ----------------- |
| `0x00 ~ 0x1F` | 保留地址          |
| `0x20 ~ 0x3F` | CAN 设备地址段    |
| `0x40 ~ 0x5F` | 以太网设备地址段  |
| `0x60 ~ 0x7F` | Wi-Fi 设备地址段  |
| `0x80 ~ 0x9F` | 蓝牙设备地址段    |
| `0xA0 ~ 0xBF` | 4G 蜂窝设备地址段 |
| `0xC0 ~ 0xDF` | RS485 设备地址段  |
| `0xE0 ~ 0xFF` | 保留地址          |

---

## 5. type 类型

| 类型值        | 定义               |
| ------------- | ------------------ |
| `0x00`        | 端到网关心跳       |
| `0x01`        | 网关到端心跳       |
| `0x02`        | 端到网关健康度     |
| `0x03`        | 网关到端健康度     |
| `0x04 ~ 0x0A` | 网络鉴权           |
| `0x0D ~ 0x12` | 服务区索引         |
| `0x15 ~ 0x1E` | 网络隧道与端口映射 |
| `0x1F ~ 0x46` | 保留               |
| `0x47`        | modbusRTU          |
| `0x48`        | modbusTCP          |
| `0x49`        | RAW_CAN            |
| `0x4A`        | CAN_FD             |
| `0x4B`        | CAN_ISOTP          |
| `0x4C`        | UDS                |
| `0x4D`        | J1939              |
| `0x4E`        | CANOPEN            |
| `0x4F ~ 0xFF` | 保留               |

`type` 只描述 payload 语义，不直接规定物理出口或转发策略。

---

## 6. 基础合法性约束

anyMSG 接收方至少应检查：

1. `msg_length >= 40`；
2. `msg_length == 40 + payload_length`；
3. 实际接收字节数等于 `msg_length`；
4. `__RESERVED__`、`__SRCHLD__`、`__PADDING__` 按当前约定填 0；
5. `destination_cid`、`source_cid` 的地址首字节属于已定义或保留地址段；
6. `type` 属于已定义或保留类型范围；
7. payload 解析不得越过 `payload_length` 指定范围。

业务层、物理接口层和共享内存层可以增加额外校验，但不得改变上述帧结构定义。
